# Code of conduct

This project exists because a routine fix for broken audio on a Mac was
needlessly hard to run without sight. That purpose sets the tone.

## What is expected

**Assume the person you are talking to knows their own setup.** Contributors
here use different macOS versions, different screen readers, different audio
interfaces and different DAWs, and a thing that is obviously true on one of
them is regularly false on another. "That works fine for me" is the start of a
diagnosis, not the end of one.

**Describe things in words.** Not everyone reading can see a screenshot, a
video, or "the highlighted line". Say what was on screen, or what was spoken.
This is a practical requirement, not a courtesy — a bug report nobody can read
is a bug report nobody can fix.

**Take accessibility problems seriously when they are reported.** If someone
says the tool says nothing, talks over itself, or puts a password prompt
somewhere their screen reader cannot reach, that is a real defect in this
project and not a preference.

**Be patient with people learning.** Some contributors here are sending their
first pull request, and some are working through an AI assistant. Both are
welcome.

## What is not acceptable

Harassment, insults, or demeaning comments. Discrimination on any basis,
including disability. Sustained disruption of discussion. Publishing anyone's
private information. Dismissing accessibility reports as user error without
looking.

## Scope

This applies in issues, pull requests, commit messages and code review — in
short, anywhere the project happens.

## Reporting

Report a problem to the maintainer, [@Matthew2244](https://github.com/Matthew2244),
through GitHub. Reports are handled privately. If the problem is with the
maintainer's own conduct, GitHub's own reporting route is at
https://github.com/contact/report-abuse.

Responses are proportionate: usually a word in private, occasionally an edited
or removed comment, and in a serious or repeated case a block from the
repository.
